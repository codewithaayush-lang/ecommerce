# Meridian Goods

A full-stack e-commerce application built as a portfolio project.

```
Browser
  → Next.js (App Router, JavaScript, Tailwind CSS)   presentation layer
  → Django + Django REST Framework                    source of truth
  → PostgreSQL
```

The frontend never talks to the database or the API directly from the browser.
All Django traffic is proxied by the Next.js server, which keeps the session
cookie HTTP-only and removes the need for CORS.

## Features

- Public product catalog with search, category filtering and pagination
- Django session authentication (register, login, logout)
- Per-user persistent cart with server-side price and stock validation
- Transactional checkout with row-level stock locking
- Order history built from immutable price/name snapshots
- Order cancellation that restores reserved stock

## Prerequisites

- Node.js 20.9+ (developed on 26)
- Python 3.14
- PostgreSQL running locally

## Local development

### 1. Database

```bash
cd backend
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
sudo bash scripts/setup_database.sh   # creates the `ecommerce` role and database
```

Create your local environment file:

```bash
cp .env.example .env
```

Then set a secret key:

```bash
.venv/bin/python -c "from django.core.management.utils import get_random_secret_key as k; print(k())"
```

Paste the output into `DJANGO_SECRET_KEY` in `.env`, and set `POSTGRES_PASSWORD`
to the password used by `setup_database.sh`. Apply migrations and run:

```bash
.venv/bin/python manage.py migrate
.venv/bin/python manage.py runserver
```

The API is then on <http://localhost:8000/api>.

### 2. Frontend

```bash
cd frontend
npm install
cp .env.example .env.local
npm run dev
```

The site is then on <http://localhost:3000>.

## Configuration

All configuration comes from environment variables. See
`backend/.env.example` and `frontend/.env.example`.

In production the backend **refuses to start** if `DJANGO_SECRET_KEY`,
`DJANGO_ALLOWED_HOSTS` or `POSTGRES_PASSWORD` is missing, or if the secret key
is still the development fallback. `DJANGO_DEBUG` defaults to `false`, so an
unconfigured deployment never serves tracebacks.

## Deployment

`render.yaml` defines a Render blueprint: a PostgreSQL database, a Django web
service, and a Next.js web service.

```bash
render blueprint launch    # or: New > Blueprint in the Render dashboard
```

After the first deploy, set two values that Render cannot infer:

| Variable | Where | Value |
|---|---|---|
| `DJANGO_ALLOWED_HOSTS` | API service | the API hostname, e.g. `ecommerce-api.onrender.com` |
| `NEXT_PUBLIC_API_URL` | Web service | `https://<api-host>/api` |

`NEXT_PUBLIC_API_URL` is inlined at build time, so changing it requires a
redeploy of the web service.

`DJANGO_SECRET_KEY` is generated by Render and injected automatically.

## Security notes

- Session cookies are HTTP-only, `SameSite=Lax`, and `Secure` whenever
  `DJANGO_DEBUG` is false.
- All writes require a CSRF token; no endpoint is `csrf_exempt`.
- Prices, totals and stock are always recomputed server-side. Values sent by
  the browser are ignored.
- Carts and orders are scoped to the authenticated user; another user's rows
  are not found, and return 404.
- The browser receives a Content-Security-Policy and related security headers
  from `next.config.mjs`.
- API errors return JSON. Unhandled exceptions are logged server-side and
  replaced with a generic message.
